AULA 01 Fundamentos de Memória RAM

Como Funcionam Variáveis, Endereços Hexadecimais e Ponteiros

Quando você declara uma variável em C++, o computador reserva um espaço na memória RAM. Cada espaço possui um endereço único em formato hexadecimal (ex: 0x7FF64A2...). Um ponteiro é uma variável que armazena esse endereço de memória. 

#include <iostream>

int main() {
    int vidaDoPersonagem = 100; // Aloca 4 bytes na memória RAM com valor 100
    int* ptrVida = &vidaDoPersonagem; // O operador '&' pega o endereço exato na RAM

    std::cout << "Endereço na RAM da Vida: " << ptrVida << "\n";
    std::cout << "Valor lido através do ponteiro (*ptr): " << *ptrVida << "\n";

    // Alterando o valor diretamente no endereço de memória
    *ptrVida = 75;
    std::cout << "Nova vida após modificação direta: " << vidaDoPersonagem << "\n";
    return 0;
}
AULA 02 WinAPI & Leitura de Processos

Abrindo Processos Externos com OpenProcess e ReadProcessMemory

Para ler informações de outro aplicativo no Windows (como a vida de um jogo), solicitamos uma permissão chamada HANDLE ao sistema operacional com o comando OpenProcess e fazemos a leitura com ReadProcessMemory. 

#include <windows.h>
#include <iostream>

int main() {
    DWORD processId = 4592; // ID do processo (PID) visível no Gerenciador de Tarefas
    
    // Solicita autorização de leitura ao Windows
    HANDLE hProcess = OpenProcess(PROCESS_VM_READ | PROCESS_QUERY_INFORMATION, FALSE, processId);
    if (!hProcess) {
        std::cerr << "Falha ao abrir o processo. Execute como Administrador!\n";
        return 1;
    }

    uintptr_t enderecoAlvo = 0x7FF6B2A10000;
    int bufferLeitura = 0;
    SIZE_T bytesLidos = 0;

    // Realiza a leitura do bloco de memória do processo
    if (ReadProcessMemory(hProcess, (LPCVOID)enderecoAlvo, &bufferLeitura, sizeof(bufferLeitura), &bytesLidos)) {
        std::cout << "Leitura concluída com sucesso! Valor: " << bufferLeitura << "\n";
    }

    CloseHandle(hProcess); // Sempre feche o Handle para economizar recursos
    return 0;
}
AULA 03 Varredura de Padrões (SigScan)

Signature Scanning: Localizando Funções Sem Depender de Updates

Offsets fixos deixam de funcionar quando o jogo atualiza. O Signature Scanning resolve isso procurando uma sequência única de bytes (máscara) na seção de código do programa. O caractere ? (wildcard) ignora valores que mudam a cada atualização. 

// Exemplo de padrão no estilo IDA Pro: "48 8B 0D ? ? ? ?"
// 0x48 e 0x8B são instruções assembly estáticas do processador x64.
// Os '?' indicam os bytes dinâmicos que o algoritmo ignora durante a busca.
